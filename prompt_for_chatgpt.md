# Context for ChatGPT: Routine AI (WellnessIQ) Project

I am working on a comprehensive, multi-page web application called **Routine AI** (also known as **WellnessIQ**). It is a health ecosystem that leverages Machine Learning and Generative AI to provide personalized health, lifestyle, and wellness recommendations.

Here is a detailed breakdown of the project so you understand the context of my questions.

## 1. Tech Stack
*   **Backend framework**: Python with Flask, Flask-CORS
*   **Database**: SQLite (`users.db`)
*   **Machine Learning**: Scikit-Learn (models saved as `.pkl`), Pandas for data formatting.
*   **Generative AI**: Google Generative AI (Gemini API)
*   **Frontend**: HTML (Jinja2 templates), Vanilla CSS, JavaScript.
*   **Authentication**: Werkzeug for password hashing, session-based login.

## 2. Core Architecture & Data Flow
1.  **User Input**: The user logs into their dashboard and submits their daily health metrics: age, gender, weight, goal, sleep hours, stress level, and steps walked.
2.  **ML Prediction (Baseline)**: 
    *   The backend takes this data, formats it into a Pandas DataFrame, and uses pickled Label Encoders (`input_encoders.pkl`) to transform the inputs.
    *   It passes the data to a pre-trained Scikit-Learn model (`model.pkl`).
    *   The model predicts 5 baseline categories: Workout Plan, Diet Plan, Lifestyle Changes, Mental Care, and Hair/Skin Care.
3.  **Gen AI Generation (Personalization)**: 
    *   The raw ML output is combined with the user's profile and fed into the Google Gemini API using an engineered prompt.
    *   Gemini acts as an expert coach and translates these raw baselines into warm, encouraging, Markdown-formatted actionable advice.
    *   *Fallback*: If the Gemini API fails, there is a static fallback mechanism that generates basic advice based on the user's raw inputs.
4.  **Frontend Display**: The Markdown generated by Gemini is sent via JSON to the frontend and rendered for the user dynamically.

## 3. Database Schema
The SQLite database (`users.db`) has two main tables:
*   `users`: Stores `id`, `username`, `password` (hashed), and `role` (defaults to 'user', but the very first registered user becomes 'admin').
*   `health_logs`: Stores `id`, `user_id` (foreign key), `goal`, `sleep_hours`, `stress_level`, `steps_walked`, and `timestamp`. This is used to track progress over time.

## 4. Key Features & Modules
*   **Authentication & Roles**: Protected routes using custom decorators (`@login_required`, `@admin_required`). 
*   **Admin Dashboard**: Shows platform-wide metrics (total users, total assessments, average sleep, average stress, and the most common health goals) using SQL aggregation queries.
*   **Multilingual Support (i18n)**: Users can switch languages. If the user selects Hindi ('hi'), the backend appends an instruction to the Gemini prompt to output the response entirely in conversational Hindi (Devanagari script).
*   **Advanced Detailed Analysis Module**: Users can request deep-dives into specific topics. Gemini adopts a specific persona (e.g., "Fitness Coach" or "Clinical Nutritionist") and outputs a daily/weekly routine formatted strictly as a Markdown table.
*   **Hair & Skin Care AI Module**: A specialized section where Gemini acts as a Dermatologist/Trichologist, analyzing the user's hydration, sleep, and stress to provide "Skin Glow" and "Hair Health" insights based on the ML baselines.
*   **Global Theme Sync**: The frontend supports global dark mode/light mode synchronization with JavaScript state persistence across all pages.

## 5. File Structure Overview
*   `app.py`: The core backend logic (routing, DB queries, ML loading, Gemini API calls).
*   `train_model.py` / `evaluate_models.py`: Scripts used to train the Scikit-Learn models on `advanced_routine_dataset_1000.csv`.
*   `users.db`: The SQLite database.
*   `model.pkl`, `input_encoders.pkl`, `output_encoders.pkl`: The Machine learning artifacts used during prediction.
*   `templates/`: Contains HTML files (home, login, register, dashboard, progress, admin, hair_skin, etc.).
*   `static/`: Contains the CSS and JS files for the frontend styling and interactivity.
